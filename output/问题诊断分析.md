# Point2Roof 重建效果差的根本原因分析

## 一、问题现象

测试结果（checkpoint_epoch_90）：
```
pts_recall: 0.071    pts_precision: 1.0
edge_recall: 0.0     edge_precision: 0.0
CF1: 0.133           EF1: 0.0
WED: 1.0             ACO: 0.0
```

每个测试样本只输出 **1个点、0条边**。模型基本处于"塌缩"状态。

---

## 二、根本原因：PointNet2 backbone 梯度无法回传（最关键）

**文件：`model/pointnet2.py`** 中的自定义 `Function` 实现：

```python
class FurthestPointSampling(Function):
    @staticmethod
    def backward(ctx, grad_out): return ()          # ← 梯度为 0

class GatherOperation(Function):
    @staticmethod
    def backward(ctx, grad_out): return None, None  # ← 梯度为 0

class ThreeNN(Function):
    @staticmethod
    def backward(ctx, a=None, b=None): return ()    # ← 梯度为 0

class ThreeInterpolate(Function):
    @staticmethod
    def backward(ctx, grad_out): return None, None, None  # ← 梯度为 0
```

### 这导致了什么？

PointNet2 的 U-Net 结构如下：

```
l0_xyz, l0_fea  →  SA1 → SA2 → SA3 → SA4
                   ↑                   ↓
                   FP1 ← FP2 ← FP3 ← FP4
                     ↓
               l0_fea → shared_fc → cls_fc / offset_fc → Loss
```

- `SA模块` 依赖 `BallQuery + GroupingOperation`（backward 为 None）
- `FP模块` 依赖 `ThreeNN + ThreeInterpolate`（backward 为 None）
- `GatherOperation` 用于 FPS 采样后提取特征（backward 为 None）

**结果：梯度从 loss 出发，经过 `cls_fc → shared_fc` 后，在进入 `FP1` 时被阻断。**
整个 SA/FP backbone 的权重**从未被更新**，始终保持随机初始化。

唯一能学习的只有 `shared_fc`(Conv1dBN 128→128) 和 `cls_fc`(Conv1d 128→1)、`offset_fc`(Conv1d 128→3) 这3层。

---

## 三、分类 Loss 被负样本主导（次要原因）

### 3.1 正负样本比例失衡

点云归一化到 [0,1]，`PosRadius = 0.15`。

假设每栋建筑约 10 个 GT 关键点，关键点附近 0.15 半径的区域只覆盖约 3-5% 的点，即约 120-200 个正样本 / 4096 总点数。

实际训练日志显示：

```
Epoch 90: pts_cls_loss=0.001, pts_acc=1.0
```

- `pts_cls_loss = 0.001` 非常低，说明模型已经收敛
- `pts_acc = 1.0` 表示所有被标记为正样本的点都被正确预测（recall 高 on training set）
- 但 offset_loss ≈ 0 说明正样本数量极少

根据 BCE loss 公式估算：`0.001 ≈ N_pos × (-log(1 - pred)) / (N_pos × batch_size)`

推算每个样本只有约 **2-3 个正样本点被激活**。

### 3.2 Loss 函数的权重设计问题

```python
# pointnet2.py 中的 get_cls_loss
cls_weights = (negatives * 1.0 + positives * 1.0).float()   # 正负权重相同
pos_normalizer = positives.sum(1, keepdim=True).float()
cls_weights /= torch.clamp(pos_normalizer, min=1.0)
```

这个"归一化"实际上只是把正样本权重除以 N_pos，**负样本权重不变**，每个负样本的权重仍然是 1/N_pos。总负样本贡献 = N_neg × (1/N_pos) ≈ 4096/N_pos >> 正样本贡献。

模型通过将所有点预测为 0（负样本）就能获得极低的 loss，这是一个"平凡解"（trivial solution）。

### 3.3 对比：原版使用 Focal Loss

原版 Point2Roof 使用 `SigmoidFocalClassificationLoss`：

```python
# loss_utils.py 中已存在该类，但未被使用
focal_weight = alpha_weight * torch.pow(pt, self.gamma)   # gamma=2.0
```

Focal Loss 会自动降低 easy negative 的权重，让模型关注 hard example。你当前的代码**没有使用 Focal Loss**。

---

## 四、下游模块级联失败

由于 PointNet2 输出的正样本点极少，后续模块全部失效：

| 模块 | 现象 | 原因 |
|------|------|------|
| ClusterRefineNet | refine_offset_loss ≈ 0 | DBSCAN 无法在极少的正样本点上形成聚类 |
| EdgeAttentionNet | edge_cls_loss = 0, edge_acc = 0 | 无聚类中心 → 无关键点对 → 无法预测边 |
| 测试输出 | 每样本 1 点、0 边 | ScoreThresh=0.2 过滤后仅剩 1 个低分点 |

---

## 五、修复建议（按优先级）

### 修复 1（必须）：替换 Loss 函数为 Focal Loss

**文件：`model/pointnet2.py`**

将 `SigmoidBCELoss` 替换为已有的 `SigmoidFocalClassificationLoss`：

```python
# 在 __init__ 中
from utils.loss_utils import SigmoidFocalClassificationLoss
self.add_module('cls_loss_func', SigmoidFocalClassificationLoss(gamma=2.0, alpha=0.25))
```

Focal Loss 的 `gamma=2.0` 会自动降低 easy negative 的梯度贡献，迫使模型学习区分正负样本。

### 修复 2（必须）：修复 PointNet2 的 backward 实现

**文件：`model/pointnet2.py`**

`pointnet2.py` 中的纯 PyTorch 实现缺少正确的梯度计算。需要修复以下 4 个类的 backward：

1. `GroupingOperation.backward` - 需要实现 scatter_add 梯度
2. `ThreeNN.backward` - 需要传播梯度到输入坐标
3. `ThreeInterpolate.backward` - 需要按权重分发梯度
4. `GatherOperation.backward` - 需要 scatter 梯度

**最简方案：用 `pointnet_stack_utils.py` 中已有正确 backward 的实现替换**，并相应修改 `PointNetSAModule` 和 `PointNetFPModule` 使用 stacked 格式（batch_cnt）而非 batch 格式。

`pointnet_stack_utils.py` 中的对应实现：
- `GroupingOperation`：有完整 backward（index_add_ 实现）
- `ThreeNN`：有完整 backward
- `ThreeInterpolate`：有完整 backward
- `ball_query`：使用 stacked 格式

### 修复 3（推荐）：增加正样本权重

在 `get_cls_loss` 中给正样本更高的权重：

```python
cls_weights = (negatives * 1.0 + positives * 5.0).float()   # 正样本权重提高到 5
```

### 修复 4（推荐）：适当增大 PosRadius

当前 `PosRadius: 0.15`，可尝试增大到 `0.2` 或 `0.25`，增加正样本数量。

---

## 六、总结

```
┌──────────────────────────────────────────────────────────────────┐
│  根本原因 #1（最致命）：                                        │
│  PointNet2 的 4 个自定义 Function 的 backward 全部返回 None/()  │
│  → SA/FP backbone 权重从未更新 → 特征表达能力为零               │
│                                                                  │
│  根本原因 #2（加重问题）：                                      │
│  使用普通 SigmoidBCELoss 而非 Focal Loss                        │
│  → 负样本主导梯度 → 模型塌缩为"全部预测负样本"的平凡解          │
│                                                                  │
│  级联效应：                                                      │
│  PointNet2 无输出 → ClusterRefineNet 无法聚类 → EdgeNet 无法学习│
│  → 测试时每个建筑只输出 1 个点、0 条边                         │
└──────────────────────────────────────────────────────────────────┘
```

**建议优先修复 #1 和 #2，然后重新训练，预期效果会有质的飞跃。**
